# Pixous i18n + engine - known quality issues (measured)

## 1. Untranslated-source retention (engine quality, not SDK)
The IndicTrans2 200M distilled models occasionally leave an individual source
word untranslated, while translating the rest of the sentence and preserving
all placeholder markers exactly. Measured 2026-10-27 against the local sidecar:

- Identical sentence, 10 different randomized marker prefixes: 6/10 fully
  translated, 4/10 kept "Nested"/"inline" in English (markers intact).
- Batch composition ruled out: same sentence solo vs in mixed batches returns
  byte-identical output.
- Deterministic for a given input; variance comes from the per-load random
  marker string shifting subword tokenization.

Status: quality-evaluation case for the native-speaker QA gate (all six
languages). SDK behavior in every observed case was correct (markers validated,
blocks applied or safely preserved). Possible engine-side lever: evaluate an
allowlist of marker variants that empirically translate fully (trades away
per-load randomization; needs product/security sign-off).

## 2. Marker validation rejects valid translations without pad trimming (FIXED)
Engines legitimately pad slot text around markers ("<x0> text </x0>"), which
produced a spurious pieces/slot count mismatch. Fixed by trimming only the
leading/trailing empty segment; every other mismatch still fails closed
(original block preserved + state="partial"). Regression case retained in the
deterministic suite.

## 3. Stale-check marker mismatch (FIXED)
buildSkeletonFromValues emitted legacy hardcoded markers while the rest of the
SDK used the randomized prefix, forcing every skeleton block into the
preserve-original path. Fixed; regression case retained.

## 4. Safe-failure contract (verified, unchanged by fixes)
Marker drop/reorder/malformed -> original block preserved + state="partial",
no fragment fallback, no retry storm. HTTP 500 -> originals + state="error".
Page content can never collide with markers (randomized prefix + collision
detection skips the block).

## 5. Observer follow-up passes wedged after first pass (FIXED)
inFlight was assigned the return value of done.finally(...) - a NEW promise -
so the clearing comparison never matched and late-arriving DOM content was
never translated after the first pass completed. Fixed by tracking the actual
promise. Regression: dynamic-node race case in the deterministic suite.

## 6. Queued observer pass fired after language switch (FIXED)
The debounced MutationObserver pass re-checked inFlight but not the current
language/generation, so a pass queued before a switch back to the source
language fired afterwards and "translated" English to the target. translateRoot
now bails when the generation changed or the active language is the source
language. Regression: switch-to-source-mid-flight case in the race suite.

## 7. Marker loss mechanism (characterized, accepted design limit)
100 sentences x 5 Indic languages, three placeholder styles: marker survival
83-87%, source-word echo 0-1%. Marker drops are caused by word REORDERING in
translation (SOV targets): placeholders attached to moved/merged words are
dropped by the model. Placeholder style does not fix reorder-driven loss, so
engine-side shielding is NOT justified by the data. The SDK fails closed on
every such case (original block preserved + state="partial"), so the user
impact is an untranslated block, never a corrupted page. Real page skeletons
carry 1-3 markers, not the 4-per-sentence worst case measured here.

## Session 2026-10-27 additions (SDK hardening)

8. Bug #6 - stale-check rejected the SDK's own prior-language translations on language-to-language switches (old skeleton markers no longer in DOM). Fixed with slot-level original-or-ours staleness (skeleton/text/merged). Pinned by race/regression suites.
9. Echo retention: for ta/hi/te/ml/kn targets, translations whose Latin-script fraction exceeds echoLatinThreshold (default 0.6) are rejected as untranslated echoes; block preserved as original + partial status. Fail-closed quality case, not silent success.
10. markerRetry (opt-in, default false): one bounded batched re-fetch per pass with a fresh randomized marker prefix (max markerRetryMax=10 skeletons/pass). Measured: 5/6 fresh prefixes recover a loss; representative 1-3 marker blocks are 96% (48/50) intact, 2% echo. Root cause: SOV reordering drops placeholders on moved words; prefix-dependent.
11. markFactory config seam for deterministic tests.

12. Echo guard extended to plain text/attribute/merged blocks (previously skeleton-only). Exemptions: URLs, emails, and cfg.echoAllowlist entries are stripped before the Latin fraction. Classification: HEURISTIC partial guard, not semantic quality assurance - English-heavy legitimate UI needs the allowlist. Plain-text echo failures are not retried (no prefix dependence); skeleton failures get the one bounded markerRetry.

13. In-text interpolation tokens ({{x}}, ${x}, %s/%d, ICU {name}) could be TRANSLATED by the engine (observed: te {{date}}->{{తేదీ}}, kn {{date}}->{{ದினాంक}}). FIXED in SDK: tokens are protected with collision-safe randomized markers before send, strict identity/count validation on receipt, fail closed (original + partial) on mismatch; skeleton blocks additionally get the one bounded markerRetry. Real-engine regression: te/kn now render {{date}} verbatim. Literal/adversarial marker-shaped page text triggers prefix regeneration (tested).
14. "Sign out" -> ta engine output reads as "Sign IN" (opposite meaning); short context-less imperative labels are a known engine quality weakness. NOT silently resolved: the string stays a flagged quality case in the review fixture. Feasible mitigation shipped: config `overrides` glossary (exact-match, per-language, integrator-supplied; none shipped by default; applied without an engine call; exempt from the echo heuristic). This is the established i18n message-catalog pattern, not per-project hardcoding.

15. Positional printf tokens (%s/%d/%i/%f) bind by ORDER, so reordering them would silently bind values to wrong words. restoreTokens now enforces source order among positional tokens (named tokens {{x}}/${x}/{name} may reorder freely - SOV correctness). Deterministic test: reversed-marker fixture - single-positional + named reorder applies; multi-positional reorder fails closed (original + partial).

## Session 2026-10-27 additions (second pass: polarity guard + retry default + chatbot boundary)

16. Round-trip polarity guard (SDK, default ON): short blocks (<= roundTripMaxChars, default 60) are back-translated after each pass and compared against a small polarity-pair table (sign in/out, log in/out, on/off, enable/disable, open/close, show/hide, lock/unlock, yes/no, allow/deny, accept/reject, start/stop, enter/exit + -ed forms). A detected opposite-meaning flip fails closed: original preserved + state="partial", and the rejected string is never re-sent on later passes. Guard errors (back-translate batch failure or malformed/unverifiable entries) ALSO fail closed: original preserved + partial, never serve an unchecked short label. TOKEN-BEARING short labels (e.g. "Deny {{name}} access") are checked too: tokens are STRIPPED from both source and translation before the back-translation, and polarity is verified on the remaining words; if stripping leaves nothing verifiable, the block fails closed (original + partial). Regression: deterministic fixture flips "Deny {{name}} access" -> "Allow access" and the SDK preserves the English original. The pair table is a bounded heuristic: 95-example zero-false-positive measurement is evidence, not production semantic proof. MEASURED: 19 strings x 5 languages on the real engine = exactly 1 flag (the true "Sign out" -> ta "Sign IN" defect), zero false positives. A generic token-F1 round-trip detector was REJECTED by measurement (misses the flip at 0.67 via shared token "sign"; false-flags good paraphrase "Contact us" -> "Get in touch with us" at 0.00). Config: roundTripCheck (bool, default true), roundTripMaxChars (int, default 60), roundTripLanguages (array, default all supported). Verified: deterministic fixture suite + live interception of the actual ta defect (test-roundtrip.js, 11/11).

17. markerRetry default flipped to TRUE with MEASURED BOUNDS (test-retrybounds.js, 7/7): zero extra calls on clean passes (tokenok: 1 vs 1 fetch OFF/ON); exactly ONE extra bounded batched fetch on lossy passes (flaky: 2 vs 1). NEGATIVE CACHE (failedAttempts) with explicit invalidation semantics: a block is stranded only after failedBlockMaxAttempts (default 2) FAILED fetch attempts - transient failures recover on a later pass (flakyonce fixture: 2,1 measured); keys are PER-LANGUAGE (stranded ta does not strand hi, measured); the map is SESSION-scoped (an engine/model/config change implies a fresh init/session); clearCache() fully resets (measured re-fetch after reset). Storm bound measured: every pass <= 2 fetches, stranded by pass 4 (a retry that succeeds with a fresh random prefix is NOT cacheable across passes - marks are randomized per pass - so one extra bounded refetch can precede stranding; bounded, never a storm). Privacy: the retry re-sends only skeletons already sent to the SAME self-hosted endpoint - no new data exposure, no third party. Opt-out preserved (markerRetry: false).

18. Chatbot self-hosted LLM: ACTUAL local boot boundary measured in a 2 GB RAM sandbox (llama-cpp-python 0.3.36, CPU). Qwen3-0.6B Q8_0 (official Qwen/Qwen3-0.6B-GGUF, rev 23749fefcc72300e3a2ad315e1317431b06b590a, apache-2.0, gated:false) boots and serves the full 15-section system prompt end-to-end through SampleApi -> OpenAiCompatible provider at n_ctx 2048. At n_ctx 4096 the process is OOM-killed mid-prompt (anon-rss 1.82 GB at kill; observed in dmesg). So the sandbox proves WIRING only, not deployable quality: EN instruction-following is acceptable, but ta/hi factual answers were WRONG (measured), and empty <think></think> tags leaked into the reply text (Qwen3 chat template emits them even with /no_think). FIXED provider-side: ThinkTagFilter (OpenAiCompatibleOptions.StripThinkTags, default true) strips think blocks including tags split across streaming SSE chunks, preserves legitimate text and dangling partial tags, drops unterminated think tails; 17 unit tests + live verification (non-streaming reply and SSE stream both clean). Residual: whitespace around a stripped block is preserved (UI trims).
   DISCLOSURE - ThinkTagFilter is an OUTPUT CONVENTION, not a security, reasoning-suppression or privacy boundary: it matches only exact lowercase "<think>...</think>" pairs (case variants like "<Think>" pass through as text), strips the FIRST close tag (nested opens are consumed; a trailing close remains literal text), strips literal tag pairs a user discusses in chat content by the same convention, and cannot detect reasoning a model emits WITHOUT the tags. Adversarial unit tests pin each of these behaviors. The recommended Qwen3-4B-Instruct-2507 (see CHAT-MODEL-RECOMMENDATION.md) needs ~3-4 GB+ RAM and was NOT bootable in this sandbox; that remains an owner hardware decision, not a code blocker.

20. DOM-insertion safety (SDK, audited + pinned 2026-10-27): engine output reaches the page ONLY through node.nodeValue writes (plain text, merged, and skeleton slots) and setAttribute on a bounded attribute list (title, alt, aria-label, placeholder, button-input value). There is no innerHTML/outerHTML/insertAdjacentHTML anywhere in pixous-i18n.js, the SDK never creates elements from translations, and URL-bearing attributes (href/src/action) are never translated - so a hostile or buggy engine cannot inject markup, elements, inline handlers, or javascript: URLs through the translation path. Structural property, not a heuristic: it holds even when every quality guard passes the text through. PINNED by test-xss.js (14 checks, deterministic "xss" fixture mode): a translation carrying <svg onload=...>, <img onerror=...>, and a literal <script> tag across a plain block, a skeleton block with a real link, and alt/title attributes results in zero executed payloads, zero new elements, zero inline handlers, the hostile markup present as literal inert text, the original link/href untouched, and state=done. Safety here is independent of the echo/round-trip guards: the fixture payload was deliberately sized to PASS the Latin-fraction echo guard, proving the write path alone is sufficient.
